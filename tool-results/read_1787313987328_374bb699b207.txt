  1644→      // Logical input format (Arabic label first, colon, then digits):

  1648→      //   The user reported that the previous layout ("numbers before

  1650→      //       text → colon → numbers

  1659→      //   direction. With RTL base, runs are placed right-to-left in
  1660→      //   logical order, so:
  1661→      //     - The Arabic run (first in logical) goes to the RIGHT side.
  1662→      //     - The colon (next) goes to the MIDDLE.
  1663→      //     - The digits run (last in logical) goes to the LEFT side.
  1664→      //   This produces exactly the desired visual layout.
  1665→      //

  1667→      //   detection appears to ignore it (both with and without LRM, the
  1668→      //   visual output is identical), but keeping it makes the intent
  1669→      //   explicit and protects against any future BiDi implementation
  1670→      //   that might honor LRM as a base-direction hint. The LRM is
  1671→      //   stripped automatically by drawMixedTextCharByChar (Cf char)
  1672→      //   AFTER BiDi processing, so it never renders as tofu.
  1673→      //
  1674→      //   The PREVIOUS layout used `${licNum} : رقم الترخيص` (digits

  1677→      //   "digits → colon → text" (numbers before text), which is what
  1678→      //   the user objected to.

  1680→      // Why char-by-char (not drawMixedText):
  1681→      //   PDFKit's internal BiDi + `features:["rtla"]` path works in local
